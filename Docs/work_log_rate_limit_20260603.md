## 1. 개요 및 설계 (Blueprint)
사용자의 스토리지 비용을 효율화하고, 임시 파일 보존 및 보안 요구사항을 만족시키기 위해 **일일 업로드 한도 제어(Rate Limit)** 및 **임시 만료 정책**을 적용했습니다.

### 등급별 세부 정책
1. **비로그인 (익명 사용자)**:
   * 일일 제한: 하루 최대 3개 업로드
   * 보존 기간: 1일(24시간) 유지 후 배치 작업에 의해 물리적 자동 삭제
2. **구글 로그인 사용자**:
   * 일일 제한: 하루 최대 10개 업로드
   * 보존 기간: 7일(168시간) 유지 후 배치 작업에 의해 물리적 자동 삭제
3. **관리자 (`mosebb@gmail.com`)**:
   * 일일 제한: 제한 없음 (무제한)
   * 보존 기간: 영구 보존 (`expires_at = null`)

## 2. 구현 내용 (Worker)

### `components/UploadZone.tsx`
* **KST(한국 표준시) 자정 리셋 시각 계산**:
  * 업로드 검증이 UTC 기준으로 동작하여 사용자가 오인하지 않도록, `UTC+9` 시간 오프셋을 적용해 한국 기준 매일 00:00:00 시각을 구한 뒤 이를 ISO 형식(`YYYY-MM-DDT00:00:00+09:00`)으로 가공하여 쿼리 조건으로 사용했습니다.
* **DB 사전 누적 카운트 조회 (Pre-flight Guard)**:
  * 업로드 진행 직전에 Supabase DB `media_files` 테이블에서 현재 유저(`user.id`)의 오늘 KST 자정 이후 업로드 레코드 개수를 카운팅합니다.
  * `supabase.from('media_files').select('*', { count: 'exact', head: true }).eq('user_id', user.id).gte('created_at', kstMidnightIso)` 쿼리를 이용해 네트워크 데이터 오버헤드 없이 빠른 Count 연산을 수행합니다.
* **업로드 한도 초과 예외 처리 및 차단**:
  * `현재 업로드 수 + 시도하려는 파일 개수 > 한도`인 경우, 에러 메시지를 노출하고 프로세스를 즉시 탈출시킵니다.
  * 비로그인 상태일 때는 구글 로그인을 수행할 수 있도록 친절하게 안내 메시지를 보여줍니다.
* **하단 자동 보존 정책 배너 업데이트**:
  * 기존 정책 안내 배너 문구를 실제 변경된 한도와 일치하도록 다듬어 렌더링하도록 갱신했습니다.

## 3. 에러 발생 및 해결 (Solver)

### 문제점: 익명 사용자의 일일 제한 처리 및 우회 차단 검토
* **에러/이슈**: 비로그인 사용자는 브라우저 쿠키를 제거하거나 시크릿 탭을 실행하면 Supabase가 새로운 익명 사용자(`signInAnonymously()`) 세션을 발급하여 `user_id`가 변경되므로 한도가 초기화되는 취약점이 있습니다.
* **해결 및 의사결정**:
  * 이를 IP 기반으로 차단하게 될 경우, 같은 사무실/카페 등 공용 네트워크 환경에서 다른 사용자가 차단당하는 오동작이 발생할 가능성이 높습니다.
  * 따라서 UX의 부작용을 예방하기 위해, **"익명 임시 세션 ID + DB 누적 카운트"**를 현 구조의 최적의 타협안으로 선정하여 적용했습니다. 이후 브라우저 핑거프린팅 등을 대안으로 활용할 수 있도록 가이드를 남겨두었습니다.
